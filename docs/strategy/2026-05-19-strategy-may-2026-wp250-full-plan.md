## Что мы строим: картинка целого

**IWE** (Intellectual Work Environment) — это персональная интеллектуальная среда, которая помогает человеку расти от случайного читателя до системного деятеля с помощью ИИ-агентов, методологии и цифрового двойника.

**Ключевая идея:** человек входит через простую точку (пост в соцсети или лендинг), постепенно получает всё более персонализированный опыт, а система ведёт его по ступеням, начисляет баллы, даёт руководства и подсказки. На каждом этапе он видит свой прогресс и понимает, зачем двигаться дальше.

**Что должно работать к концу мая:**
- Пользователь заходит с лендинга или поста → попадает в бота.
- В боте проходит диагностику, узнаёт ступень, видит баллы.
- Получает персональное руководство (через тайный Гит или явный GitHub — по выбору).
- Видит табло с прогрессом: ступень, баллы, что делать дальше.
- ИИ-агенты (Диагност, Навигатор, Портной, Аттестатор) следят за прогрессом и подсказывают.
- Марафон для новичков работает стабильно: задания приходят, система видит выполнение.
- Служба Хелпдеска принимает сигналы от пользователей и видит здоровье платформы.
- Маркетолог, деканат и финансисты видят табло по движению пользователей.

## Пять интерфейсов и путь пользователя

> **Примечание:** в разговорной речи мы говорим «пять интерфейсов», но технически это четыре интерфейса плюс точка входа (лендинг). Лендинг — не интерфейс работы, а дверь.

| Этап | Интерфейс | Что пользователь делает | Что получает |
|------|-----------|------------------------|--------------|
| **0. Точка входа** | Лендинг / пост в соцсети | Читает, нажимает кнопку | Понимание ценности, ссылка на бота |
| **1. Первый контакт** | Telegram-бот | `/consent`, `/diagnose`, `/slot` | Ступень, баллы, первый ритм |
| **2. Погружение** | Браузер (Claude.ai) | `/connect`, диалог с агентами | Навигатор, Диагност, персональные рекомендации |
| **3. База знаний** | Тайный Гит / Явный GitHub | `/personal-guide-start` или авто-рендер | Персональное руководство, обновляемое ежедневно |
| **4. Полная среда** | VS Code | Day-open, day-close, стратегия | Полный IWE, все агенты, редактирование руководства |

**Путь пользователя:**

```
Лендинг / Пост
    ↓
Бот (T1): диагностика, марафон, баллы
    ↓ (активен 3+ дня)
Браузер (T2): Навигатор, Диагност
    ↓ (заинтересовался руководством)
Гит-руководство (T3): персональный план
    ↓ (хочет углубиться)
VS Code (T4): полная среда
```

**Важно:** переход между этапами добровольный, но система предлагает его в нужный момент. Например, бот сам пишет: «Вы 3 дня подряд записываете время — хотите посмотреть персональное руководство?»

## Фаза 1: Стабилизация текущей когорты (19–25 мая)

**Цель:** 5+ пилотов из 9 имеют работающее руководство, ритм `/slot` и корректные баллы.

### Что делаем

**19–20 мая (Пн–Вт):**
- [ ] **Диагностика воронки** (WP-188): SQL-запрос — где пилоты застревают (consent → diagnose → link → personal-guide-start).
- [ ] **Портной smoke** (WP-149): 1 пилот получает сгенерированное руководство корректно.
- [ ] **Сообщение #7** (`/slot`) — отправить wave-1.
- [ ] **Realtime `/points`** — проверить все 9 пилотов, убедиться что <30 сек.
- [ ] **WP-237** — архитектурное решение по audit trail.

**21–22 мая (Ср–Чт):**
- [ ] **Портной** — масштаб на 3 пилотов.
- [ ] **WP-253** — bulk-onboarding wave-2 (15 человек), если opt-in позволяет.
- [ ] **Табло MVP** — хотя бы 1 дашборд (деканат) с реальными данными.
- [ ] **Марафон** — финализация контента, проверка доставки.

**23–25 мая (Пт–Вс):**
- [ ] **Smoke wave-1** — 3 пилота проходят полный путь: бот → диагностика → /slot → руководство → баллы.
- [ ] **WP-311 Ф-Close** — финальный smoke баллов (7-й день когорты).
- [ ] **Обновление лендинга** — тексты согласованы, вёрстка начата.

### Критерий выхода из Фазы 1

- [ ] ≥5 пилотов: руководство сгенерировано и обновилось хотя бы 1 раз.
- [ ] ≥5 пилотов: `/slot` сделан ≥3 дня подряд.
- [ ] Баллы в `/points` корректны для всех 9 (smoke: баллы ≠ 0).
- [ ] ≥3 пилота прошли марафон-неделю без блокеров.
- [ ] Табло деканата живо с реальными данными.

**Цель:** путь пользователя замкнут от лендинга до руководства, тайный Гит готов к пилоту, хелпдеск принимает сигналы.

- [ ] **Тайный Гит MVP** (WP-309-Ф8): системное репо, рендер туда, дайджест в боте. Smoke: 1 пилот без GitHub-аккаунта получает руководство.
- [ ] **Лендинг** (WP-304): обновлён, деплоен, кнопка ведёт в бота.
- [ ] **Табло** — 3 дашборда (маркетолог, деканат, финансист).
- [ ] **Хелпдеск MVP** — `/support` в боте, тикеты падают в канал, SLA 24ч.
- [ ] **Хермес-агенты MVP** — сбор из клуба (1 источник), дайджест для пилота.

**28–31 мая:**
- [ ] **Универсальные руководства** (WP-332) — заготовки stage×domain для конвейера.
- [ ] **Граф понятий MVP** — связка основных Паков, базовая онтология.
- [ ] **Пак риторики** — структура + 3 метода.
- [ ] **Расширение Экстрактора** — W-рефлексии, кейсы.
- [ ] **Nudge-система** (WP-117) — автонапоминания при 3 днях без активности.
- [ ] **D7/D30 alerter** (WP-244) — запуск на данных wave-1.
- [ ] **Руководства под Дизайном** (WP-329) — стартовый набор.

### Критерий выхода из Фазы 2 (конец мая)

- [ ] Пользователь может зайти с лендинга, пройти в бота, получить ступень, баллы, руководство.
- [ ] Тайный Гит работает для 1 пилота (smoke).
- [ ] Табло видят маркетолог, деканат, финансист.
- [ ] Хелпдеск принимает обращения.
- [ ] Хермес даёт первый дайджест.
- [ ] Nudge работает (автонапоминания).
- [ ] Граф понятий — базовая связка Паков.

## Что остаётся на июнь

Эти задачи важны, но не блокируют майские критерии. Если ресурсы останутся — берём в май. Если нет — первая неделя июня.

| Задача | Почему не в мае |
|--------|-----------------|
| Подписка-gate (бесплатно / платно) | Требует бизнес-решение, которое не должно торопиться |
| Полный emitter (WP-214 Ф3–Ф6) | Cedar policies — объёмная задача, риск сломать текущий поток |
| Двухслойная среда (WP-308) | Архитектура, не блокирует текущих пилотов |
| Развитие агентов (learning) | Требует данных от wave-1, которых пока мало |
| Масштаб Хермеса (LMS + гит + другие источники) | MVP только клуб, остальное — расширение |
| Полный конвейер руководств | Требует стабильного Портного, который ещё в Фазе 1 |

## Что могло быть упущено — проверочный список

Этот раздел — страховка. Если что-то из списка ниже важно, оно добавляется в план.

### Техническое

- [ ] **Производительность рендера:** при 15+ пилотах рендер не должен падать по таймауту. Сейчас timeout 60с, запас 300с. Нужен мониторинг.
- [ ] **Масштаб баллов:** при wave-2 (15 чел.) + wave-3 (30 чел.) worker должен держать realtime. Сейчас cursor=max, но нагрузка вырастет.
- [ ] **GitHub rate limits:** при массовом создании репо `personal-guide` для wave-2 — риск упёреться в лимиты API.
- [ ] **Backup перед wave-2:** перед bulk-onboarding — обязательный бэкап всех 7 БД.

### Пользовательское

- [ ] **Fallback для пилотов без GitHub:** тайный Гит решает это, но нужен сценарий «хочу перейти на явный позже».
- [ ] **Мобильный опыт:** большинство пилотов заходят с телефона. Лендинг и бот должны работать на мобильном без прокрутки вбок.
- [ ] **Язык:** все тексты на русском? Англоязычные пилоты (если появятся) — отдельная задача.

### Бизнесовое

- [ ] **Цена подписки:** где проходит граница бесплатного / платного? Это бизнес-решение, блокирует R2.
- [ ] **Оплата:** YooKassa / Stars / autopay — статус для wave-2?
- [ ] **Оферта ИП:** нужна для приёма платежей. Готова?
- [ ] **Refund policy:** что если пилот заплатил и передумал?

### Организационное

- [ ] **Передача продукта менеджеру:** Ильшат к 1 июня должен принимать продуктовые решения. Как идёт передача?
- [ ] **Bus factor:** если Дима заболеет — кто чинит Портного? Если Ильшат — кто ведёт воронку?
- [ ] **Sync ИТ ↔ продвижение:** еженедельная встреча запланирована? Каждая ли состоится?

### Юридическое

- [ ] **PII:** хранение персональных данных 7 лет (WP-237) — архитектура решена?
- [ ] **Cedar policies:** formalization secrets БД — актуально?
- [ ] **GDPR / consent:** механизм opt-out работает? Правильно ли логируется?

### Контентное

- [ ] **Программа ЛР vs РР:** порядок — сначала ЛР (есть), потом РР (новое). Не смешиваем.
- [ ] **Методология ступеней:** cp.iwe recommendations — не противоречат ли текущим критериям FORM.089?
- [ ] **W-рефлексии:** влияют на gate Д→П. Кто их рецензирует?
