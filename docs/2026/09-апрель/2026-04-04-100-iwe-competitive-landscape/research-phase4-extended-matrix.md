## 1. Методология оценки

<details open>
<summary><b>10 параметров и шкала</b></summary>

| # | Параметр | 0 = отсутствует | 1 = зачатки / частично | 2 = полноценно реализовано |
|---|----------|-----------------|------------------------|---------------------------|
| 1 | **Ядро мышления** | Нет иерархии знаний. Заметки = плоский список | Есть структура папок/тегов, но без формализованной иерархии и fallback chain | Формализованная иерархия знаний (типа ZP->FPF->SPF->Pack->DS), source-of-truth, fallback chain |
| 2 | **Культура работы** | Нет протоколов, нет gate-проверок | Есть шаблоны/SOPs, но без формализованных gates и фрактальных масштабов | Формализованные протоколы (ОРЗ-фрактал, gate-протоколы), навыки, форматы на 3+ масштабах |
| 3 | **Модель мастерства** | Нет траектории роста пользователя | Есть уровни/тиры, но без персональной программы развития | Формализованная траектория (уровни с критериями), персональная программа, измеримый прогресс |
| 4 | **Сообщество** | Нет сообщества или только баг-трекер | GitHub Issues/Discord для техподдержки | Сообщество как среда развития: network effects, менторство, совместная работа, «место для жизни» |
| 5 | **ЦД (Цифровой Двойник)** | Нет модели пользователя | Базовый профиль/preferences, память сессий | Живая модель: компетенции, интересы, стратегия, траектория. Автообновление. Используется для персонализации и рекомендаций |
| 6 | **Дистрибутив (ОС, не платформа)** | Закрытый SaaS, данные на сервере вендора | Open-source, но требует конкретного хоста/вендора | Всё в открытых форматах (Git, Markdown, YAML), пользователь владеет данными, git clone = забрать всё |
| 7 | **Vendor-agnostic** | Привязан к одному LLM/вендору | Поддерживает 2-3 провайдера, но с ограничениями | Работает с любым LLM, знания переживают смену вендора |
| 8 | **Экзокортекс-подход** | AI = автопилот / «сделай за меня» | Элементы усиления мышления, но без формализованного human gate | Расширение мышления, human gate обязателен, экзоскелет != автопилот — как принцип |
| 9 | **Онбординг и доступность** | Нет документации, нужен эксперт для старта | Есть README/docs, старт за 30-60 мин | Guided setup за 15 мин, интерактивный онбординг, новичок продуктивен с первого дня |
| 10 | **Зрелость и активность** | Заброшен или <100 звёзд, нет документации | Активен, 1-10k звёзд, базовая документация | 10k+ звёзд ИЛИ коммерческий продукт, полная документация, регулярные релизы, устоявшееся сообщество |

## 3. Детальный анализ Tier 1

<details open>
<summary><b>3.1 PAI -- Personal AI Infrastructure (Daniel Miessler)</b></summary>

**Оценки по 10 параметрам:**

| Параметр | Оценка | Детали |
|----------|:------:|--------|
| Ядро мышления | 1 | TELOS-файлы (самоопределение: цели, вызовы, метрики) = аналог Pack, но без иерархии ZP->FPF->SPF. Нет fallback chain. Нет разделения доменное/реализационное |
| Культура работы | 1 | SOPs есть, хуки есть, но нет фрактальных масштабов (сессия/день/неделя). Нет формализованных gates. Набор практик, не ОС |
| Модель мастерства | 1 | PAIMM (Personal AI Maturity Model): 3 тира (Chatbots->Agents->Assistants), 6 измерений прогрессии. Но это модель зрелости **инструмента**, не **пользователя**. Нет траектории «я как профессионал расту» |
| Сообщество | 1 | GitHub Discussions, 30+ контрибьюторов, подкаст Unsupervised Learning. Техническое сообщество, не среда развития |
| ЦД | 1 | TELOS = профиль пользователя для AI (цели, вызовы, метрики). Но нет автообновления по активности, нет модели компетенций, нет траектории |
| Дистрибутив | 2 | Markdown-файлы, Git, USER/SYSTEM разделение. Пользователь владеет данными |
| Vendor-agnostic | 2 | Через Fabric работает с 40+ LLM-провайдерами. Реально портируемый |
| Экзокортекс | 2 | «Magnifying HUMAN capabilities» -- формализованный принцип. Не автопилот, а усиление |
| Онбординг | 1 | TELOS-онбординг за 10-15 мин, но это только конфигурация профиля, не guided tour по всей системе. Нужно понимать Fabric, Git, CLI |
| Зрелость | 2 | 11k звёзд PAI + 40k звёзд Fabric. v4.0.3. Активные релизы. Личный бренд Миесслера. Подкасты, блог, конференции |

**Что есть у PAI, чего нет у IWE:**
1. **Реальный vendor-agnostic через Fabric.** 40+ LLM-провайдеров. IWE де-факто привязан к Claude
2. **PAIMM -- модель зрелости AI-использования.** IWE фокусируется на мастерстве пользователя, но не на зрелости его взаимодействия с AI
3. **Публичность и бренд.** 11k+40k звёзд, подкасты, конференции. IWE -- внутренний проект
4. **Портирование на OpenCode.** Сообщество уже портировало PAI на альтернативный CLI (pai-opencode). Доказательство реальной vendor-agnostic архитектуры
5. **Terminal UI с голосом.** PAI поддерживает голосовой ввод через CLI

**Где IWE сильнее PAI:**
1. **Ядро мышления глубже.** Pack с иерархией ZP->FPF->SPF->Pack->DS, fallback chain, source-of-truth -- PAI не имеет этого
2. **Культура работы формализованнее.** ОРЗ на 3 масштабах, gate-протоколы -- PAI имеет SOPs, но не систему
3. **ЦД полноценнее.** Компетенции, стратегия, траектория, автообновление -- PAI имеет только TELOS-профиль
4. **Модель мастерства пользователя.** Ученик->Просветитель = рост человека. PAIMM = рост инструмента

</details>

### Итоговая диагностика

**IWE уникален по глубине (параметры 1-5, 8):** ни один конкурент не приближается к формализации мышления, культуры работы и модели мастерства.

**IWE критически отстаёт по доступности (параметры 9-10):** система непередаваема, невидима и привязана к одному вендору.

**Парадокс:** самая глубокая система в нише одновременно самая недоступная. Глубина без доступности = система одного пользователя. Доступность без глубины = ещё одна PKM-обёртка.

**Стратегический вывод:** приоритет #1 -- не углублять уникальность (она уже подтверждена), а делать её передаваемой. Онбординг + публикация + vendor-agnostic = три ключа к превращению IWE из персонального проекта в продукт.
