Несколько месяцев строил AI-экосистему без единого инженерного стандарта. Сегодня прогнал ревизию по 12 факторам Heroku.

🚨 Главная находка: **15 production-сервисов из 28 не имеют CI deploy**. Push в GitHub ничего не триггерит. У 5 Railway-воркеров нет `RAILWAY_GIT_*` env vars — деплоятся через `railway up` с локальной машины. У 10 Cloudflare Workers нет `wrangler-action` в `.github/workflows/` — `wrangler deploy` тоже локально.

Что это значит на практике: production runtime не привязан к git commit. Нельзя сказать, какой код сейчас в проде. Нельзя сделать rollback к конкретному SHA. При security-инциденте разборка займёт часы вместо минут.

При этом архитектура сама по себе оказалась здоровой: stateless по дизайну, FSM в БД, workers на DB-cursor с idempotency, 0 hardcoded secrets. То есть фундамент к масштабированию готов — а вот деплой-пайплайн дырявый.

Итог: 155 ✅ (46%), 71 ⚠️ (21%), 33 ❌ (10%) из 336 ячеек compliance-матрицы. DoD «100% green» не достигнут — впереди 22 часа фикс-работы.

В посте — полная таблица 28×12, что вышло хорошо/плохо, методологические уроки и **жёсткое заключение ИИ-критика на основе двух независимых review**.
