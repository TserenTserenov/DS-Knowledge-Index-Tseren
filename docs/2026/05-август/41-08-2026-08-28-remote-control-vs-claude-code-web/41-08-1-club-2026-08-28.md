# Что на самом деле продолжается, когда я открываю Claude Code с телефона

На днях я открыл Claude на телефоне и увидел баннер «Remote Control активен». Обрадовался, потом сам себе задал вопрос: а что именно я сейчас вижу — ту же самую рабочую среду, что на Mac, или что-то новое? Начал разбираться и понял, что путал два разных продукта, которые выглядят одинаково, а работают по совсем разной архитектуре.

## Задача

Мне нужно было понять: могу ли я полноценно работать с телефона — с той же памятью, с теми же ~40 репозиториями моей личной среды IWE — или это только подсматривание за прогрессом. И отдельно — можно ли вообще обойтись без компьютера, если однажды его не будет под рукой.

Ответ оказался «и то, и другое возможно», но это два разных пути, и путать их — значит настраивать не то и удивляться результату.

## Архитектура: зеркало против чистого листа

**Remote Control** ничего не запускает сам. Сессия обязательно стартует на компьютере — командой `claude` в терминале или в VS Code. Дальше телефон просто подключается к этому уже идущему процессу: через QR-код, через ссылку, или — если я залогинен на claude.ai тем же аккаунтом — система сама предлагает открыть активную сессию, без сканирования. Технически это зеркало: тот же процесс, тот же диск, та же память.

**Claude Code on the web** (claude.ai/code) устроен ровно наоборот. Это отдельная облачная песочница Anthropic, которая создаётся с нуля прямо в браузере. Я подключаю GitHub, выбираю один репозиторий из списка — и работаю в изолированном контейнере, который вообще не знает о существовании моего Mac.

Разница проявляется в трёх местах, которые я проверил на практике.

**Память.** У Remote Control она такая же, как у обычной сессии на компьютере — вся накопленная история в `memory/`, уроки, feedback, контекст прошлых разговоров доступны как есть. У claude.ai/code память по умолчанию не копится вообще: песочница эфемерна, создаётся под сессию и уничтожается после неё. Переживает только то, что я явно закоммитил и запушил в git. Не «то же самое, только на серверах Anthropic» — принципиально другая модель.

**Число репозиториев.** У меня на Mac рабочая директория `~/IWE/` физически содержит около сорока репозиториев. Remote Control зеркалит именно её — значит с телефона видно всё сразу, без выбора. claude.ai/code клонирует ровно один репозиторий на сессию, и его нужно явно выбрать из списка подключённых через GitHub. Хочешь другой — либо новая сессия, либо `git clone` руками внутри уже идущей.

**Подписка.** Remote Control требует Claude Max ($100 или $200 в месяц). claude.ai/code работает уже с обычным Claude Pro ($20). Это не мелочь — если задача просто «дать новичку попробовать в браузере», Max не нужен вообще.

## Реализация

Проверил на своей машине: CLI Claude Code уже поддерживает нужный флаг —

```
claude --remote-control
```

— это открывает обычную интерактивную сессию с включённым Remote Control, показывает ссылку и QR-код. Есть и «серверный» вариант без интерактивного окна:

```
claude remote-control
```

VS Code тут не обязателен как программа — обязателен живой процесс CLI на компьютере, в терминале или в VS Code, без разницы.

Отдельно проверил параллельную работу. claude.ai/code сам изолирует каждую облачную сессию на отдельную git-ветку — несколько сессий не пишут в один checkout одновременно, конфликта записи файлов нет. Конфликт может возникнуть только на этапе слияния веток в `main`, если две сессии правили один файл — обычный git-конфликт, решается вручную. У Remote Control такой изоляции нет вообще: это просто ещё один вход в тот же процесс, поэтому вся инфраструктура для параллельных локальных сессий (раннер, блокировки на файлы) — отдельная задача, никак не связанная с Remote Control.

## Ограничения

Компьютер для Remote Control должен быть включён и не спать — иначе сессия рвётся. Я специально проверил: таймер сна по бездействию у меня был давно отключён, а вот закрытие крышки ноутбука усыпляет машину отдельным механизмом, независимо от этого таймера. Без внешнего монитора единственный рабочий способ — `sudo pmset -a disablesleep 1` (полный запрет сна, обратимо через `disablesleep 0`). У ноутбука без подключённого дисплея вентиляция при закрытой крышке хуже, поэтому не стоит держать так машину постоянно под тяжёлой нагрузкой — но для лёгкой работы агента риск небольшой.

Для claude.ai/code эта проблема просто не существует — облачная песочница не зависит от того, спит ли мой компьютер. Зато там нет накопленной памяти и нет доступа сразу к нескольким репозиториям — и это осознанный компромисс архитектуры, а не недоработка.

## Что я теперь делаю иначе

Продолжаю рабочую сессию на Mac и приглядываю за ней с телефона — беру Remote Control, без вариантов: там моя память и все репозитории сразу. Если нужно быстро показать что-то новичку, у которого ещё нет ни настроенного окружения, ни накопленного контекста — claude.ai/code, потому что порог входа ниже (обычный Pro) и не нужно ничего готовить заранее.

Это не конкурирующие инструменты, а два разных ответа на вопрос «откуда я хочу продолжить работу»: из своей истории или с чистого листа.
