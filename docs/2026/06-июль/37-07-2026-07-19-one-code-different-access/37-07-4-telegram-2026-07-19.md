# Код один, доступ разный

Долго думал, что код роли, которая касается личных данных, придётся писать дважды: один раз для открытого комплекта, один раз для закрытой платформы. Разбор конкретного кода показал другое.

Нашёлся живой симптом: коды одной роли в каталоге принципов платформы разошлись с тем, что реально в открытом репозитории, кто-то правил одну копию и забыл про вторую.

Принцип, который приняли: один канонический код роли, платформа импортирует напрямую. Разница между открытым и закрытым режимом не в коде роли, а в отдельном слое доступа к данным.

Честно: сама по себе идея ничего не гарантирует, безопасность зависит от того, как спроектирован конкретный слой доступа. Перенос роли, которая касается личных данных, ждёт отдельной проверки безопасности, прежде чем код станет открытым.

Полный разбор с оценкой по архитектурным критериям в клубе.
