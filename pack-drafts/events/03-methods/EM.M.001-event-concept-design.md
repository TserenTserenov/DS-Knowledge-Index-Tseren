# EM.M.001 · Event Concept Design — Разработка концепции мероприятия

## Назначение

Трансформировать запрос заказчика в чёткую концепцию мероприятия, которую можно бюджетировать, продюсировать и оценивать. Результат метода — утверждённый **Event Brief (EM.WP.001)**.

## Алгоритм

### Шаг 1. Понять цель (зачем)

Задать заказчику прямой вопрос: «Что изменится в мире или в вашей организации после этого мероприятия?» Цели бывают:
- **Коммуникационные**: донести стратегию, объявить запуск
- **Социальные**: объединить команду, создать сообщество
- **Коммерческие**: привлечь лиды, закрыть сделки
- **Образовательные**: повысить компетенции, передать знания

Одно мероприятие = одна приоритетная цель. Остальные — дополнительные.

### Шаг 2. Определить аудиторию (кто)

- Кто эти люди? (профессия, уровень, интересы)
- Что они хотят получить от мероприятия?
- Что они НЕ хотят (какой опыт их разочарует)?
- Размер аудитории: это влияет на формат и бюджет

### Шаг 3. Выбрать формат (как)

Формат = функция (цель × аудитория × бюджет). Основные форматы:
- Конференция / форум: много контента, широкая аудитория
- Воркшоп / мастерская: практика, малая группа 15–40
- Гала / церемония: празднование, награждение
- Стратегическая сессия: управленческая команда, фасилитация
- Митап / нетворкинг: сообщество, неформальность

### Шаг 4. Сформулировать ценностное предложение

Одно предложение: «После этого мероприятия [аудитория] получит [результат], которого не получит нигде ещё».

### Шаг 5. Согласовать ограничения

- Дата (жёсткая / гибкая)
- Бюджет (верхняя граница)
- Место (город, формат: офлайн/онлайн/гибрид)
- Команда (кто реализует)

### Шаг 6. Зафиксировать в Event Brief

→ Передать в EM.WP.001

## Типичные ошибки

- Начинать с площадки вместо цели
- Не спрашивать «зачем» — получать размытый запрос «сделайте нам что-нибудь крутое»
- Смешивать цели заказчика и цели аудитории (см. EM.FM.003)

|---|---|
| **Входы** | Запрос заказчика, бюджет, дата, аудитория |

| **Время** | 1–3 рабочих встречи с заказчиком |
