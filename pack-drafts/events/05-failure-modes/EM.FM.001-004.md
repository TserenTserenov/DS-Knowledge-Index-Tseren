# EM.FM.001 · Scope Creep без пересмотра бюджета

## Описание

Заказчик (или команда) добавляет новые элементы после утверждения концепции и бюджета, не инициируя пересмотр ни того ни другого.

**Типичные проявления:**
- «Давайте добавим ещё одного спикера-звезду» (уже после верстки бюджета)
- «Можно сделать видеосъёмку со всех углов?» (за неделю до события)
- «А давайте устроим ещё и фуршет после»
- «Нам нужно 50 дополнительных мест, площадка справится»

## Почему это происходит

- Организатор боится говорить «нет» заказчику
- Нет явного изменения статуса брифа при изменении scope
- Заказчик не понимает связь: запрос → деньги → время

## Последствия

- Мероприятие уходит в минус
- Команда работает сверхурочно, выгорает
- Качество страдает: делали много, сделали плохо
- Отношения с заказчиком портятся (он думает, что «всё получилось само»)

## Профилактика

1. **Event Brief как контракт**: любое изменение scope = новая версия брифа = пересогласование
2. **Change request процесс**: письменный запрос → оценка стоимости → решение заказчика
3. **Фраза-якорь**: «Это возможно. Это добавит X ₽ к бюджету и Y дней к подготовке. Подтверждаете?»
4. **Бюджетный резерв**: 15% только на форс-мажоры, не на scope creep

## Связанные сущности

- EM.D.001 (Мероприятие ≠ Проект) — корень проблемы: мышление «доделаем»
- EM.FM.002 (Timeline Compression) — часто сопутствует

# EM.FM.002 · Timeline Compression

## Описание

Поздние решения заказчика сжимают фактический срок подготовки. Организатор получает бюджет и задачу за 3 недели до события, хотя стандартный срок — 3 месяца.

## Последствия

- Подрядчики берут наценку 20–50% за срочность
- Нет времени на тендер и выбор лучшего
- Ошибки в коммуникациях с участниками (некорректные данные)
- Команда в режиме хаоса, риск выгорания

## Профилактика

- Утвердить минимальные сроки подготовки по типу события (и прописать в договоре)
- Ввести «gate-check»: нет брифа за N дней до события = не берёмся
- Повышающий коэффициент стоимости при сжатых сроках

# EM.FM.003 · Stakeholder Misalignment

## Описание

Разные стейкхолдеры имеют несогласованные ожидания от мероприятия. Организатор получает противоречивые указания и не может угодить всем.

**Пример:** CEO хочет брендинг и статус, HR — вовлечённость сотрудников, коммерческий директор — лиды и продажи. При этом никто из них не разговаривал между собой.

## Профилактика

- Stakeholder interview на старте: спросить каждого отдельно
- Провести alignment-встречу с ключевыми стейкхолдерами до утверждения брифа
- Зафиксировать иерархию целей в Event Brief и получить подпись

# EM.FM.004 · Single Vendor Dependency

## Описание

Ключевой элемент мероприятия обеспечивается единственным подрядчиком без резерва и без плана Б.

**Критические точки отказа:**
- Звуковой/световой подрядчик (сломался грузовик)
- Кейтеринг (отравление, задержка поставки)
- Трансляция (интернет-соединение, оборудование)
- Ключевой спикер (заболел, не приехал)

## Профилактика

- Для каждой критической зоны — план Б (резервный подрядчик, резервное оборудование)
- Contractor risk assessment: есть ли у них резервы?
- Резервный интернет-канал (мобильный роутер как минимум)
- Для ключевых спикеров: «Что делаем, если он не придёт?» — записать ответ заранее
